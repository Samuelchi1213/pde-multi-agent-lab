## 一、针对已发现问题的改动

### 1. Codex 首次开发与自动返工都有独立检查点

新增 `web_console_v1/codex_checkpoints.py`，由 `DynamicTeamRun.codex_step()` 调用：
- 首次开发步骤 `developer.first`。
- 第 n 次自动返工 `developer.rework.n`。
- 人工定向返工 `manual.rework.1`，在独立 `manual_rework_1` 任务目录管理，不覆盖原草案的历史步骤。
- 指纹绑定 Codex 模型、prompt SHA256、交付 JSON Schema SHA256、输出路径。
- 调用前先预约；只有 `reserved` 可以调用 CLI。
- CLI 成功后验证 JSON 交付内容与落盘一致，生成包含**交付 SHA256、前后程序快照摘要**的结果回执，保存并标记 completed。
- 步骤复用时，须同时验证回执完整、交付 JSON 完整、**隔离工作区程序快照仍一致**。相同已完成步骤不再调用 Codex，计数按 step_id 去重。
- 超时、部分修改、交付文件缺失、写盘异常、指纹冲突、回执或工作区改动后，都**阻止自动重跑**，保留本地成果供人工判断。

> 工作区快照只包括程序文件，不包括学生 JSON/上传文件，**不能作为生产级全部文件的版本证明**；最终发布仍需专用差异检查、原文件备份与人工确认。

### 2. 禁止危险的整目录写回

过去的 `sync_allowed_paths()` 会先清空真实项目中的目标目录再复制，包括 `src/data` 等真实记录，存在严重风险。

- 团队 QA 返回 `pass` 或 `need_human/user_acceptance` 且 Python 测试证据通过时，现在只标记 `复核通过（待安全发布）`、`qa_passed=true`、`candidate_synced=false`。
- **不会自动调用旧的目录覆盖同步**。下一步必须由用户通过“查看安全发布预览 → 确认安全发布候选版本”进行；该流程逐文件比对、排除用户数据、备份并在失败时回滚。
- 测试不通过、没有 QA 证据、或者未获得必要授权时不允许冒充发布成功。
- 已有 `apply_real_project_changes()` 改成明确拒绝直接目录同步。
- 旧控制台“发布待验收版本”按钮已隐藏；其 `/api/project/acceptance/publish-pending` 后端返回 409，**不能再绕过安全发布保护**。
- 不回退或篡改用户此前已验收的历史版本和学生数据。

### 3. 隔离快照保护学生隐私

原项目副本复制已修改为：
- 拒绝对非空的既有 staging 目录再次复制，避免任务重启清空已产生成果。
- 仅复制允许的程序/说明/配置后缀，跳过 data、uploads、backups、secrets、logs、.git、缓存、依赖文件夹。
- 不复制 `.env`、密钥、学生数据 JSON、数据库、表格和其他不必要的大文件。
- 以前已经创建的旧 staging 不自动删除或改写；如其中已有真实敏感记录，应以后单独审核清理，不能不经确认删除。
- 由此可能造成依赖媒体素材、真实数据样本或特殊配置的项目在隔离环境里缺少文件，需按实际测试补充**脱敏开发样例**，绝不为跑通测试而复制真实学生记录。

## 二、明早一键统一验证

控制台无正在执行的付费任务时：
1. “检查更新 → 立即更新 → 退出控制台 → 双击静默启动器”。
2. 展开“开发 / 诊断工具”，点击 **一键综合验收（全部离线）**。
3. 期望显示 **73 tests、退出码 0、OK/综合自检通过**。可能出现 Windows 环境不支持测试创建符号链接而跳过 1 项；skip 不等于失败。
4. 用户提供最终结果截图；发现 FAIL/ERROR/未达到 73 项则暂停后续真实任务，先修复对应代码。

## 三、B2 尚未完成的部分

**B2 当前是 Codex/DeepSeek 两端“检查点防重复”，而不是完整的任务工作流“自动恢复”。**

- 预算批准后，只继续缺失步骤的**状态机执行器**尚未建立。旧危险预算整队重跑已安全关闭；因此预算不足的真实任务暂时只能暂停/待人工处理。
- 已中断且结果未知的 Codex/DeepSeek 不能自行解锁重试。
- 无法仅凭程序快照判断模型是否对外部系统产生了副作用；本方案基于隔离本地 CLI，不得用来自动重复支付、发布等高风险操作。
- 旧历史任务没有检查点的阶段不能自动追认，不得因为新版上线而直接重新执行。
- 未做真实付费模型端到端试运行，必须先通过 73 项离线/模拟测试，再评估最小、低成本隔离试运行。
- 发布路径和阶段恢复仍需要更严格的真实 Windows 测试，包括日志、审批、数据完整性和发布回滚。
