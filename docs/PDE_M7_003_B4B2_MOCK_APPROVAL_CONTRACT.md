## 三、模拟审批契约

假审批必须在下列条件同时成立时才能在**独立测试内**签发：

1. B4-B0 原始任务状态为 `review_candidate`，B4-B1 假执行阶段资格为 `ready_fake_only`，两者都不得附带真实执行权限。
2. 普通 `DRAFT-*` 任务明确指定单个 `step_id`。把原始 `state/draft/ledger` 三个文件的 SHA256 与任务/步骤合并计算证据绑定指纹。
3. 单个测试审批必须包括 `requester`、与其不同的 `approver`、明确 `approved=True`、请求 SHA256、模拟 credits 上限、开始/到期的测试刻度。
4. 同一任务同一步骤只允许一次内存签发，过期不会自动续签；每张假审批只能消费一次，线程并发消费也只能有一次模拟成功。
5. 消费前必须复核任务、阶段、当前证据绑定、请求指纹和模拟额度。任何变更、过期、超支都冻结该假审批，后续不得重放。
6. 即使消费成功，也只返回 `mock_approved_for_fake_step_only`，始终 `can_resume_now=false`、`resume_authorized=false`、`external_model_calls=0`、`real_project_writes=0`。

**注意：** 测试刻度不是生产时钟；内存哈希收据不是签名授权，不具备跨进程持久化与防伪能力，更不允许用作真实模型调用令牌。

## 四、Windows 验收方法

1. 确认没有付费任务执行，控制台检查更新 → 立即更新 → 退出控制台 → 重新双击静默启动器。
2. 展开「开发 / 诊断工具」，点击「一键综合验收（全部离线）」。
3. 期望 `Ran 180 tests`，综合自检通过，退出码 0，外部模型请求无，真实项目写入无。某些 Windows 环境可有 `skipped=1`。
4. 在旧 `VALIDATE-REWORK-1791377437` 团队执行区域点击「查看逐步骤恢复预览（只读）」。
5. 预期显示「B4-B2 逐步骤模拟审批资格（只读，无实际审批）」「审批资格：安全阻断」，B4-B1/B4-B0/B4-A 继续安全阻断。
6. 截图反馈，禁止通过创建实际付费团队任务来取得测试数据。
