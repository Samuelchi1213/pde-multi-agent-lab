## 本次实际改动

1. `DynamicTeamRun.use_ds(..., step_id=)` 已接入真实的 DeepSeek 调用路径：
   - `product.spec`、`architecture.plan`、`qa.review.0` / `qa.review.1` ...
   - 调用前根据角色、模型、系统提示与结构化输入计算 SHA-256 指纹；**不把原始 Prompt 或密钥写入检查点**。
   - 新调用在预算允许时先持久预约；只有获得 `reserved` 才可以调用 DeepSeek。
   - 响应成功时在 `artifacts/deepseek_step_<step_id>.json` 原子保存结果/usage，再验证 SHA-256 回执并标记完成。
   - 已完成且指纹/回执匹配的步骤，只读加载回执，不再次调用 DeepSeek。
   - 外部调用错误、超时或落盘失败时标记结果不确定；未来不能自动再次请求。
   - `billed_step_ids` 仅按步骤累计一次调用和 token；崩溃于“写回执后、计账前”时，可从可信回执补记。
   - 预算预检查**先于预约**；预算不足不产生假“请求已发送”。
2. 将旧的“同意追加预算→重新执行整支团队”的真实任务路径改为明确 HTTP 409 安全拦截；模拟预算审批功能仍可用。
   - 原实现会新建一个 `DynamicTeamRun`，重新 `run()`，进而重做产品/架构/Codex 并可能清空隔离工作区；**存在重复付费/覆盖成果风险**。
   - 新版遇到真实任务预算追加申请时保留原预算申请、检查点、状态和隔离成果，并提示需要安全的阶段级恢复处理器。**这属于临时安全限制，不是已经实现继续执行**。
   - `decline`（先暂停）不变。
3. 新增 `web_console_v1/test_model_call_checkpoints.py`（12 项，无网络且使用模拟提供商）。
4. “开发 / 诊断工具”新增按钮 **验证模型调用防重复（模拟）**，对应 `/api/diagnostics/model-call-guard/self-test`；旧 13 项和 18 项按钮不变。

## Windows 验收

请确保没有付费模型调用正在运行，再更新 GitHub 并重启 PDE。展开开发 / 诊断工具，点击“验证模型调用防重复（模拟）”。

期望看到：
- 测试数量 12；
- 退出码 0；
- 结果 OK/模拟模型防重复通过。

12 项涵盖：首次调用/回执、重复不再发请求、带历史状态的重建、回执完成但计账未落盘、输入与系统提示变化、超时、回执篡改、预算不足不占位、超预算后保存已付款结果、结果标记写入失败不重试、不同 QA 轮次相互独立。

**未验证之前不要对真实辅导员项目发起新的多智能体付费任务。** 旧项目数据不会因为本次代码更新自动修改。

## 仍未实现、不得误报为已完成

- Codex 执行器的步骤级检查点：未接入；开发过程中断仍然需要人工判断。
- 团队级的“从未完成的步骤继续”：未接入，旧的危险预算整队重跑被临时停用。
- 模型响应到达但尚未保存回执的异常，无法证明服务器是否计费；采取冻结而非猜测重试。
- 旧任务历史中没有检查点的阶段不会自动追认为已完成；不得删除旧产物以强行重跑。
- 原有旧 `sync_allowed_paths` 有覆盖/删除真实项目文件风险，本轮未修改该路径；优先走差异预览与备份的安全发布。
- 长期跨进程状态存储、真正的任务级事务/锁、Codex 完整工作区快照，须后续单独设计。
