# PDE 多智能体团队 v1｜共享状态设计

## 目标

让多个智能体在不同职责、不同上下文下工作时，仍然保持：
- 目标一致
- 任务一致
- 状态一致
- 决策一致
- 交接可追踪

核心原则：

> 共享必要事实，不共享全部思考过程。

---

## 一、共享状态分为四层

### 第1层｜项目级共享状态

所有智能体都需要知道。

来源文件：
- PROJECT.md
- CURRENT.md
- DECISIONS.md

内容包括：
- 项目是什么
- 当前阶段
- 已确认的重要规则
- 已经做过的关键决定
- 当前整体风险和重点

作用：
防止不同智能体对“我们到底在做什么”产生不同理解。

---

### 第2层｜任务级共享状态

只要参与当前任务的智能体都需要知道。

建议未来每个任务都有独立任务文件，例如：

tasks/TASK-023.md

内容包括：
- 任务编号
- 任务目标
- 当前状态
- 当前负责人
- 已参与智能体
- 任务范围
- 非任务范围
- 验收标准
- 已完成工作
- 当前阻塞
- 返工记录
- 是否等待人工决策
- 最终结果

任务文件是智能体之间最主要的交接载体。

---

## 二、一个任务文件应该长什么样

示例：

# TASK-023｜晚返学生自动识别

## 目标
识别预计返校时间已过，但晚间考勤仍未确认返校的学生。

## 当前状态
测试中

## 当前负责人
测试智能体

## 任务等级
C级

## 本次范围
- 根据预计返校时间判断
- 结合晚间考勤结果
- 生成异常标记

## 不在本次范围
- 自动发送通知
- 自动处分
- 自动修改学生返校时间

## 验收标准
1. 正常返校学生不标记异常
2. 超过预计时间且未考勤返校的学生标记异常
3. 修改预计返校时间后状态重新计算

## 产品结论
……

## 架构结论
……

## 开发记录
……

## 测试结果
……

## 当前阻塞
无

## 人工决策
无

## 下一步
测试通过后交回项目协调智能体。

---

## 三、第3层｜角色专属上下文

不是所有信息都需要全员读取。

### 产品智能体重点读取
- PROJECT.md
- DECISIONS.md
- 当前 TASK 文件
- 产品规则相关文档

### 架构智能体重点读取
- 当前 TASK 文件
- 已确认产品结论
- architecture 文档
- database / api / permission 文档

### 开发智能体重点读取
- 当前 TASK 文件
- 架构结论
- 相关代码
- 技术规范
- 测试要求

### 测试智能体重点读取
- 当前 TASK 文件
- 验收标准
- 开发改动说明
- 测试规范

### 项目协调智能体重点读取
- PROJECT.md
- CURRENT.md
- TASKS.md
- DECISIONS.md
- 所有活跃任务的摘要状态

---

## 四、第4层｜智能体私有工作上下文

每个智能体可以有自己的临时推理、草稿、分析过程。

这些内容：
- 不需要全部写入共享仓库
- 不需要让其他智能体读取
- 不作为最终项目事实来源

只有形成结论后，才写回任务文件。

原则：

> 思考可以私有，结论必须共享。

---

## 五、智能体开始工作前必须做什么

每个智能体开始处理任务前，固定执行：

1. 读取 PROJECT.md
2. 读取 CURRENT.md
3. 读取 DECISIONS.md 中与任务有关的决定
4. 读取当前任务文件
5. 读取与自己角色有关的专属文档
6. 检查任务当前负责人是否确实是自己
7. 确认是否存在“等待人工决策”

如果任务正在等待人工决策，则不得继续执行。

---

## 六、智能体完成工作后必须写回什么

每个智能体完成一次工作后，至少更新：

- 做了什么
- 得出什么结论
- 修改了哪些内容
- 是否存在风险或阻塞
- 是否需要返工
- 下一责任智能体是谁
- 当前任务状态

如果产生新规则或重要决定：
- 更新 DECISIONS.md

如果影响整个项目当前阶段：
- 更新 CURRENT.md

---

## 七、为什么不用“共享全部聊天记录”

共享全部聊天记录会带来：
- 上下文越来越长
- 无关信息太多
- 智能体容易被旧讨论干扰
- 成本增加
- 不同智能体难以抓住真正结论

因此我们采用：

聊天 / 临时分析
→ 提炼结论
→ 写入项目状态
→ 其他智能体只读取结论和必要背景

---

## 八、共享状态的优先级

当不同来源出现冲突时，优先级建议：

1. 项目负责人最新明确决定
2. DECISIONS.md 已确认决定
3. 当前任务文件中的最新确认状态
4. PROJECT.md / CURRENT.md
5. 其他文档
6. 历史聊天记录

聊天记录不能覆盖已确认项目决策。

---

## 九、未来可升级的实现

第一阶段：
Markdown 文件作为共享状态。

后续可以升级为：
- GitHub Issues
- 数据库任务表
- 工作流状态机
- 长期记忆存储
- 向量检索
- 多智能体消息总线

但不影响核心思想：

> 项目事实必须结构化、可读取、可更新、可追踪。

---

## 十、v1 最小共享状态结构

推荐目录：

PROJECT.md
CURRENT.md
DECISIONS.md
TASKS.md

tasks/
  TASK-xxx.md

agents/
  项目协调智能体
  产品智能体
  架构智能体
  开发智能体
  测试智能体

docs/
  team-workflow-v1.md
  shared-state-v1.md

核心原则：

> 全员共享项目事实，任务参与者共享任务状态，角色只读取必要专业信息，智能体私有思考不强制共享。
