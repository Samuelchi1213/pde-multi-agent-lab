## B3.1｜2026-10-09 历史回归验证草案兼容修复（Windows 验收通过）

用户打开旧版自动返工回归验证历史记录时，恢复预览提示“草案或历史状态格式不正确”。原因：旧版 `VALIDATE-REWORK-*` 草案仅写入内存，而重启后任务状态仍在磁盘；只读预览无法获得草案。

修复如下：

- 历史任务的草案缺失/损坏或智能体名单不可信时，返回**明确的只读阻断诊断**；步骤列表为空、`can_resume_now=false`、`resume_authorized=false`，不推测智能体或自动补建检查点。
- 旧 `VALIDATE-REWORK` 任务给出专门的“旧版验证草案可能仅在内存中”提示；原 state、workspace、回执都保留，不修改旧数据。
- 新建 `VALIDATE-REWORK-*` 与 `VALIDATE-BUDGET-*` 任务时，先原子保存完整草案，再启动验证；失败则直接停止。
- 重启控制台时从原 runtime/drafts 加载这两类验证草案；无模型调用。
- 增加四项只读兼容测试和三项验证草案重启持久化测试；离线综合回归总数从 90 项变为 **97 项**，不涉及真实业务项目。

**Windows 验收**：确认未运行付费任务，控制台检查更新、更新、退出、静默重新启动，点击“开发 / 诊断工具 → 一键综合验收（全部离线）”；期望 `Ran 97 tests`、`OK`、退出码 0（Windows 可有 `skipped=1`）。随后对同一旧版验证任务点击“查看逐步骤恢复预览（只读）”；预期显示明确草案缺失及禁止续跑的注意事项，**不再显示笼统的格式错误**。截图反馈后再决定后续阶段。

**B3.1 实际验收结果（2026-10-09）**：用户提供控制台截图显示 97 项综合自检通过、退出码 0、外部模型请求为无、真实项目写入为无。对旧 `VALIDATE-REWORK-1791377437` 点击只读恢复预览后，正确显示原始任务草案缺失、步骤调用不可推断、立即自动续跑禁止，并建议保留历史数据；不再出现原先的“草案或历史状态格式不正确”错误。B3.1 关闭；正式阶段级自动恢复仍未实现。

该修复不是自动任务恢复授权，不可点击“启动团队执行”来替代验收。

## 未来真正恢复任务的准入标准（本轮未实现）

必须同时做到：
- 原始草案、授权真实项目路径和原始隔离 workspace 一致；
- 原始 state、已完成阶段回执的 SHA256 和各步请求指纹一致；
- Codex 交付以及最新代码快照可核实；
- 每阶段可追踪未执行 / 完成 / 不确定，不能靠历史调用次数猜测；
- 不重新初始化 workspace 或重新从 `run()` 开头执行；
- 额外 DeepSeek 预算得到具体步骤级授权，调用前先预约；
- 旧历史任务不自动升级为可恢复任务；不确认的阶段暂停；
- 模拟中断/断电、网页重复点击、审批重复提交、回执被改动和真实项目隔离数据都经过回归验收；
- 任何程序写回都经过独立测试、SHA 差异预览、备份和手动发布。
