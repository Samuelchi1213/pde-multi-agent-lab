# PDE M9｜返校状态核对清单：独立业务功能试点

> 开始日期：2026-10-12  
> 当前状态：**已提交可直接打开的独立页面，等待 Windows 端一次性业务闭环验收。**  
> M8 基线：236 项离线测试与模拟恢复 UI 均已验收。M9 不改变 M8 原有测试数量或付费模型授权。

## 一、为什么选择这个功能

要验证 PDE 不只是反复运行安全测试，而是能交付一个能够操作、产生表格结果的业务小工具。此前辅导员工作场景中，学生自报返校不代表真实到校，晚间考勤才是核对依据；预计返校日期可能推后，自报与实际不一致需要明确提示，不应直接覆盖学生填过的信息。

本轮**只做一个能用的核对清单**，暂不预设整个放假管理系统的流程、学校表格模板或生活委员权限。

## 二、当前功能

- 独立入口：PDE 首页「M9｜返校状态核对清单 · 真实功能试点」→「打开返校核对清单」；打开新标签 `/m9/return-checkin`。
- 自带 5 条**虚构记录**；允许逐行编辑校区、学院、班级、姓名、学号、预计返校日期、学生自报、晚间考勤和跟进备注；可以添加/删除记录。
- 日期与考勤变化后即时重新分类与更新统计，可筛选不同核对状态。
- CSV 空白模板、浏览器本地 CSV 导入（最大 300KB、500 条）、导出全部核对结果（含备注和计算状态）。
- 按原始自报与晚间考勤并列显示，不会擅自修改学生自报，也不会把「未核实考勤」当作已返校。
- 「运行规则自检」在浏览器直接执行 10 项逻辑与 CSV 规则测试，不影响现有记录。

### 分类优先级（当前可用的简单规则）

1. 晚间考勤 `未核实` → `待核实考勤`，即便学生自报已返校也不做已返结论。
2. 晚间考勤 `到校` → `已核实到校`。
3. 晚间考勤 `未到校`，但学生自报 `已返校` 或 `留校` → `信息冲突`。
4. 晚间考勤 `未到校`，预计返校日期缺失 → `待补预计日期`。
5. 晚间考勤 `未到校`，日期早于核对日期 → `逾期未到`；等于核对日期 → `今日未到`；晚于核对日期 → `预计未到`。

**注意：** 「到校」目前只代表工作人员在界面中录入的考勤值，软件尚不具备核实考勤来源和人员身份的能力。此工具不生成学生违纪、考勤处罚或学校官方到校结论。

## 三、隐私与实现边界

- 实现文件：`web_console_v1/m9_return_checkin.html`，独立 HTML + 原生浏览器 JS，不依赖三方 CDNs。
- 控制台仅通过 **GET 静态文件**提供页面，没有新的学生数据 POST/保存接口；浏览器页面不使用 `fetch`、`XMLHttpRequest`、`localStorage`、`innerHTML`、`eval`，不向服务器上传内容。
- 服务端设置 CSP（`connect-src 'none'` 等）和 `no-store` 头，页面导入/核对/CSV 导出均在当前浏览器进程执行。
- 导出 CSV 时对 `=`、`+`、`-`、`@` 等 Excel 公式前缀进行防护，减小 CSV 公式注入风险。
- **页面刷新或关闭会丢失未导出的工作数据。** 本轮不是持久数据库或可多人协作的正式学生管理系统。
- 请仅使用虚构资料完成试点。真实学生名单的导入和学校数据处理需要后续明确授权、适当的数据保护与权限设计；不使用真实辅导员工作台文件来试验。
- 真实 Codex/DeepSeek 调用、真实项目覆盖发布或 PDE 历史团队任务续跑继续关闭。

## 五、Windows 一次性功能验收

1. PDE 更新并**完整退出、重启**。首页应该看到「M9｜返校状态核对清单 · 真实功能试点」。
2. 点击「打开返校核对清单」，加载 **5 条虚构记录**。
3. 核查示例甲：学生自报 `已返校`、晚间考勤 `未到校`，应显示 `信息冲突`。
4. 将示例甲的「晚间考勤」改成 `到校`：示例甲状态应改成 `已核实到校`，上方冲突数量下降 1、已核实数量上升 1。
5. 点击「运行规则自检」，期望显示「本地规则自检通过：10 项」。
6. 点击「导出核对结果 CSV」，用表格工具打开；确认表格中含 5 条虚构记录、预计日期、自报、晚间考勤、状态、备注。
7. 反馈最多**一张工作台界面截图 + 一句 CSV 能否成功打开**即可。不需要重跑 236 项回归测试；如果旧功能明显异常，再专门复查。

## 六、完成之后再决定的事情

先确认这套状态分类符合实际核查习惯，再讨论与学校原始表、班委晚间考勤、学生助理导出权限、预计返校时间提醒之间的衔接。

**M9 这一版是可实际编辑和导出结果的独立业务小工具，不是 PDE 已自动完成真实多 Agent 付费开发任务的证明。** 后续如要把它真正接入辅导员工作台，必须先确认真实数据结构和允许写入的文件范围，不直接覆盖已有产品。
