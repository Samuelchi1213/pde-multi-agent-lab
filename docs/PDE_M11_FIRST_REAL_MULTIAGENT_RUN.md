## 1. 当前代码能力的核查（仅从 GitHub 静态源码确认）

入口：
- `web_console_v1/app.py` 的 `POST /api/analyze` 使用 `coordinator.analyze_goal`；**这一点击本身就会发起 DeepSeek API 请求**，不是免费的草案按钮。
- 用户确认草案后，`POST /api/team/start` 创建 `DynamicTeamRun` 后台线程，调用 `run()`；前置条件是已确认草案和 DeepSeek Key。
- `team_executor.py` 中产品智能体和架构智能体调用 `deepseek_json`；开发智能体调用 `run_codex`，在 `workspace-write` 沙盒运行 Codex CLI；测试智能体根据真实工作区及 `run_python_tests` 测试结果再次调用 DeepSeek QA。
- `run()` 可在测试智能体提出 `rework` 时自动最多两轮返工，因此**启动一次团队并不保证只发生一次 Codex 调用**。
- `GET /api/executors` 只验证 Codex CLI 是否可在 PATH 中找到、DeepSeek 环境变量是否存在；**不能证明登录已生效、指定 Codex 模型可用或模型费用有上限**。
- `team_executor.run_codex` 固定指定 `--model gpt-5.6-sol`，需要在用户 Windows 端验证当前 Codex CLI 实际支持。当前代码没有把 Codex 的配额或费用统一换算为人民币成本。
- `DynamicTeamRun` 默认 DeepSeek `deepseek_token_budget=16000`、`absolute_budget=30000`，但预算是在调用前检查已用 tokens，不是严格的单次请求 token/人民币价格硬上限。不能向负责人承诺“不会超过 N 元”。
- 不勾选 `use_real_project` 时只创建原始任务隔离目录 `orchestrator_v1/dynamic_runs/<DRAFT-ID>/workspace`，不复制/写入辅导员工作台。原 `run()` 会初始化状态和工作区；不得用它恢复历史失败任务。
- `step_checkpoints` 与 `codex_checkpoints` 存在回执/预约防重，但真实供应商超时或断连后仍存在未知计费风险，禁止无人工核查直接重试。

**结论：源码包含真实协调、产品、架构、开发、测试路径，但当前没有完成可核实的首轮真实自主交付；不能仅凭旧模拟测试、源码存在和 CLI PATH 显示「已连接」断言实战就绪。**

### 交给 PDE 项目协调智能体的原始需求（只在费用授权后输入）

请组织真正的多智能体团队，在一个全新的隔离工作目录内从零开发一个 **纯 Python 标准库的 CSV 行筛选小工具**，并真实运行自动测试。必须由 PDE 内部智能体完成需求分析、需要的产品/技术设计、代码实现及独立测试复核；任何代码不得由 ChatGPT 直接代写。

需求范围：
- 命令行 `python csv_filter.py --input <文件> --column <列名> --equals <值> --output <文件>`，读取 UTF-8（含 BOM）CSV，按某列精确匹配，输出保留原表头的 UTF-8 CSV。
- 非法参数、输入不存在、字段不存在、CSV 格式问题必须给出清晰错误并以非 0 码退出。
- 使用 Python 3 标准库；禁止第三方依赖、网络访问、调用外部 API、环境变量密钥读取及修改任何真实项目。
- 仅使用 `DEMO` 前缀的虚构数据，可附带示例 CSV；不得包含学生名单或其他个人资料。
- 必须在隔离目录产出 `csv_filter.py`、可被 `unittest discover` 识别的测试、`README.md` 启动说明；必须至少实测：正常匹配、无匹配、缺少字段、带 UTF-8 BOM、含逗号或换行的标准 CSV 字段。
- 不需要网页 UI、数据库、Git commit、任务自动重试或对辅导员工作台集成。
- PDE 应展示谁承担产品/架构/开发/测试工作，保留实测结果、实际工具调用及交付文件，最后由负责人验收。
- 如缺少模型授权、运行安全条件或任务负责人决策，停止并说明，绝不绕过。

### 交接及真实性证据

不是只看漂亮的任务进度条。至少必须有：
1. **协调者**：真实 `DRAFT-...` 草案及被确认的 `required_agents`。如果没有 `开发智能体` 和 `测试智能体`，不要启动，先复核草案。
