# PDE M8｜阶段恢复可操作闭环（隔离演练版）

> 日期：2026-10-12
> 状态：**2026-10-12 Windows 正常操作闭环、异常回执冻结与 236 项离线回归全部通过；M8 已验收关闭。**
> 目的：改变过度细分安全模块的开发节奏，优先交付可直接操作的产品体验。
> **重要：当前仍未开放真实历史任务的 `run_from_stage`，不调用 Codex / DeepSeek，不接真实辅导员项目。**

## 为什么改为完整里程碑交付

此前 B3–B4-C2 形成了 220 项离线测试，但用户长期只看到“只读恢复预览”和“安全阻断”，缺少实际的任务操作闭环。现在以产品使用链路为核心：**模拟创建 → 中断 → 判断可复用步骤 → 人工模拟审批 → 逐步恢复 → QA 完成 → 成果状态可见**。常规测试合并到里程碑末尾，不再每增加约 20 项测试就要求一次 Windows 验收。

## 本次可使用的功能

控制台新增独立卡片 **「阶段恢复完整演练 · 可操作版」**，置于团队执行模块前。卡片不读取真实 `DRAFT` 历史数据，也不读取当前已连接项目、学生数据或模型密钥。演练任务编号固定为 `DRAFT-DEMO-ONLY`，所有状态仅保存在当前控制台进程内存中。

- **① 创建虚构任务：** 注入产品、架构两阶段有可信模拟回执的场景；开发与测试未运行。
- **② 模拟中断：** 保存虚构的阶段完成信息并暂停推进。
- **③ 核查恢复位置：** 调用现有 B4-A 的 `simulate_stage_recovery` 确认下一步骤从 `developer.first` 开始。
- **④ 批准当前模拟步骤：** 使用已有 B4-B2 `MockApprovalBook` 的单步骤、模拟预算、不同虚构身份和指纹绑定契约（不是真实用户登录/审批）。
- **⑤ 继续当前模拟步骤：** 使用 B4-B1 `FakeStageSession` 仅在内存里模拟一次步骤执行。之后再次操作 ④ 和 ⑤，模拟 QA 验收并进入完成状态。
- **模拟回执丢失（冻结）：** 对当前已批准步骤模拟“不确定”，之后不允许再次执行同一步骤；需要重置虚构演练重新开始。
- **重置演练：** 仅清除独立内存对象，不删除本机历史项目、检查点或已保存草案。

系统显示阶段交接、下一步骤、模拟调用次数、模拟预算消耗、时间线和明确的安全边界。浏览器刷新可以保留当前进程内的演练状态，但**退出控制台会重置**。因此这一版本**不是断电后生产级可续跑**。

## 新增代码及接口

- `web_console_v1/recovery_flow_demo.py`：`RecoveryFlowDemo`，封闭、线程安全、固定虚构数据和固定操作枚举；复用已有离线阶段规划、内存模拟审批与模拟执行器，不允许传入路径、模型名称或任意执行回调。
- `web_console_v1/test_recovery_flow_demo.py`：16 项针对完整正常流程、步骤交接、显式批准、重复点击、状态变化、回执未知冻结、重置、刷新及线程重复提交的离线测试。
- `web_console_v1/app.py`：新增可操作卡片及两个独立路由（`GET /api/demo/recovery-flow` 查询内存状态，`POST /api/demo/recovery-flow` 仅允许上述 7 个固定动作）。原有真实团队执行路由不改变。
- 综合离线回归期望由 **220 项更新为 236 项**；尚待 Windows 实际验证。

## 统一 Windows 验收（只做一次，不逐小模块截图）

1. 确认没有正在进行的真实付费任务，控制台「检查更新」→「立即更新」→「退出控制台」→双击静默启动器，必须使用新页面。
2. 在首页找到「阶段恢复完整演练 · 可操作版」。依次执行：① 创建 → ② 中断 → ③ 核查 → ④ 模拟审批开发 → ⑤ 继续开发 → ④ 模拟审批测试 → ⑤ 继续测试。
3. **成功标准：** 看到「模拟任务完成」，产品/架构显示可信回执复用，开发/测试显示模拟完成；模拟步骤调用数 2、模拟预算消耗 5/5，真实模型调用和真实项目写入 0。
4. **冻结标准：** 点击「重置演练」，重新走 ①②③④，然后点击「模拟回执丢失（冻结）」。应显示冻结、模拟调用只计 1 次，继续和审批按钮不能重复启动。
5. 最后统一运行「开发 / 诊断工具 → 一键综合验收（全部离线）」，预计 `Ran 236 tests`、`OK`、退出码 0，外部模型请求无、真实项目写入无。Windows symlink 限制可导致跳过一项。
6. 反馈以**演练最终状态和错误**为主；如果全部通过，不必逐步骤提交许多截图。建议最多提供两张：正常模拟完成、冻结后状态（可附测试结果）。

## Windows 实际验收结果（2026-10-12）

- **正常演练通过：** 产品/架构可信模拟回执复用；开发/测试经过分阶段模拟审批后完成，UI 显示「模拟任务完成」、模拟调用 2、假预算 5/5。
- **异常冻结通过：** 重置、创建、中断、核查、审批并模拟回执丢失，UI 显示「结果不确定，已冻结」、假调用 1 次、模拟预算 3/5，开发及测试均仍标记尚未开始；冻结后无可继续执行的步骤按钮。
- **整体离线回归通过：** 综合测试 236 项、退出码 0、外部模型请求无、真实项目写入无。
- **M8 状态：已完成**；所有结论仅适用于固定虚构任务的内存模拟闭环，真实模型费用和真实业务文件权限仍禁用。

## 不在本里程碑内

- 不把历史 `VALIDATE-REWORK-*` 任务转为可自动恢复的真实任务。
- 不替换 `DynamicTeamRun.run()`，不创建真正的 `run_from_stage`，不涉及真实模型 idempotency / 计费。
- 不对接有真实数据的辅导员工作台，也不执行真实项目发布或同步。
- 不宣称真实断电恢复或跨进程真实费用安全已经通过。

## 下一轮里程碑（而非继续拆成 C3-A/B/C 小关口）

在这次隔离可操作闭环验收后，选择**一个可实际解决问题的真实业务闭环**：对特定历史任务从中断阶段安全继续到测试完成。必须先落实可信身份与明确费用授权、原始回执核验、模型账单未知冻结、独立执行器及可控项目工作区。届时仍需负责人确认模型、任务、费用上限和允许操作的文件，不能默认为已获批准。

**里程碑衡量方式：是否让用户完成了一整条任务流程，而非增加多少个测试。**
