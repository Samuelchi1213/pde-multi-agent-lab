# 异构多智能体执行通道评测 v1

## 目标

不预设“哪个模型/哪个CLI最好”，而是使用同一个真实小任务，对不同执行通道进行横向测试。

当前候选：
- Codex CLI（ChatGPT Plus 套餐额度）
- Claude Code + DeepSeek 模型
- DeepSeek Harness（DeepSeek API）
- 豆包 CLI（基础会员额度）
- DeepSeek 裸 API（作为低成本结构化判断基线）

## 核心原则

> 智能体角色、执行壳、底层模型、调用通道彼此解耦。

一个智能体可以表示为：

角色规则
+ 项目上下文
+ 执行壳
+ 底层模型
+ 工具权限

## 第一轮评测任务

选择一个低风险、真实、可验证的小型代码任务。

要求：
- 能读取同一个测试仓库
- 能修改少量文件
- 能运行测试或做可验证检查
- 不涉及真实学生数据
- 不涉及密钥
- 不涉及复杂部署
- 每个执行通道收到相同任务说明

## 评测维度

### 1. 自主性
- 能否自己读取仓库
- 能否自己找到相关文件
- 是否需要大量人工提示
- 是否能连续完成多个步骤

### 2. 工具能力
- 能否修改文件
- 能否运行终端
- 能否运行测试
- 能否使用 Git
- 能否限制工作目录

### 3. 稳定性
- 是否容易中断
- 是否需要频繁确认
- 是否会遗漏任务要求
- 是否会出现无关修改

### 4. 结果质量
- 是否正确完成任务
- 是否通过测试
- 是否遵守任务范围
- 是否能清楚汇报修改内容

### 5. 可编排性
- 是否支持非交互调用
- 输出能否被程序读取
- 是否有明确成功/失败状态
- 是否能被上层项目协调程序自动触发

### 6. 成本
- 是否消耗已有套餐额度
- 是否额外产生 API 成本
- 单次任务大致成本
- 是否值得用于高频任务

### 7. 适合角色
最终判断更适合：
- 项目协调智能体
- 产品智能体
- 架构智能体
- 开发智能体
- 测试智能体

## 第一轮目标

不是确定最终赢家，而是回答：

1. 哪些 CLI 真正可以被程序自动调用？
2. 哪个执行通道最适合开发任务？
3. 哪个最适合低成本分析与判断？
4. 哪个最适合作为测试/复核角色？
5. 哪些通道目前仍需要人工触发？
