# PDE 多智能体团队 v1｜任务分级与动态组队规则

## 目标

让“项目协调智能体”根据任务复杂度，决定：
- 需要哪些智能体参与
- 哪些环节可以跳过
- 什么时候需要返工
- 什么时候必须上报项目负责人

原则：**最少必要智能体原则**。

不是所有任务都经过所有角色，而是只调用完成当前任务所需的最少角色。

---

## 一、任务分级

### A级｜简单执行任务

特征：
- 目标非常明确
- 不改变业务逻辑
- 不改变系统结构
- 风险低
- 修改范围小

例子：
- 修改按钮文字
- 调整页面文案
- 修复明显样式问题
- 修复已经定位的简单 Bug

默认路径：

项目负责人
→ 项目协调智能体
→ 开发智能体
→ 测试智能体
→ 项目协调智能体
→ 完成 / 验收

---

### B级｜功能实现任务

特征：
- 需要新增或调整一个明确功能
- 业务目标基本明确
- 可能影响多个文件或模块
- 需要判断实现方式

例子：
- 增加“晚返学生标记”
- 增加导出功能
- 增加筛选功能

默认路径：

项目协调智能体
→ 产品智能体（必要时）
→ 架构智能体
→ 开发智能体
→ 测试智能体
→ 项目协调智能体
→ 项目负责人验收

如果需求已经非常明确，可以跳过产品智能体。

---

### C级｜复杂功能 / 跨模块任务

特征：
- 涉及多个模块
- 业务规则较多
- 涉及数据库、权限、接口或流程变化
- 存在明显技术取舍

例子：
- 新增完整请假模块
- 新增晚间考勤与返校状态联动
- 修改用户身份验证流程

默认路径：

项目协调智能体
→ 产品智能体
→ 架构智能体
→ 开发智能体
→ 测试智能体
→ 必要时返工
→ 项目协调智能体
→ 项目负责人验收

---

### D级｜方向性 / 高风险任务

特征：
- 改变产品方向
- 涉及核心架构
- 涉及敏感数据、权限、安全
- 涉及不可逆操作
- 存在多个方向且取舍明显
- 现有项目规则不足以判断

默认路径：

项目协调智能体
→ 组织相关专业智能体分析
→ 汇总冲突 / 方案 / 风险
→ 暂停自动推进
→ 上报项目负责人
→ 项目负责人决策
→ 项目协调智能体恢复执行

---

## 二、项目协调智能体如何选人

协调智能体先问五个问题：

1. 需求是否已经足够明确？
   - 否 → 调用产品智能体

2. 是否涉及系统结构、数据库、接口、权限或多个模块？
   - 是 → 调用架构智能体

3. 是否需要修改代码或配置？
   - 是 → 调用开发智能体

4. 是否需要验证结果？
   - 原则上所有代码改动都需要测试智能体

5. 是否出现方向性冲突、高风险或超出已有规则的问题？
   - 是 → 暂停并上报项目负责人

---

## 三、智能体之间的直接返工

允许直接返工：

测试智能体 → 开发智能体
- 明确 Bug
- 测试不通过
- 实现与验收标准不一致

开发智能体 → 架构智能体
- 技术方案无法实现
- 发现原方案存在明显结构问题

架构智能体 → 产品智能体
- 业务规则存在缺口
- 两条业务规则互相冲突

返工后，需要把结果写回当前任务状态。

---

## 四、必须经过项目协调智能体的情况

- 任务责任人发生变化
- 任务范围扩大
- 需要增加新的智能体
- 一个任务拆成多个子任务
- 多个任务存在依赖关系
- 返工超过预设次数
- 不同专业智能体意见冲突

协调智能体负责重新编排，不负责替代专业判断。

---

## 五、必须上报项目负责人的情况

满足任意一项即触发人工决策：

- 产品方向改变
- 核心业务规则改变
- 两个方案都有明显利弊
- 不同智能体结论冲突且无法根据已有规则裁决
- 涉及删除、覆盖、迁移重要数据
- 涉及隐私、安全、权限、费用
- 任务范围明显超出原计划
- 连续返工仍无法解决
- 项目资料不足，继续执行可能产生较大风险

---

## 六、第一版团队结构

项目负责人：用户本人

项目协调智能体：
- 任务分析
- 拆解
- 排序
- 动态组队
- 状态维护
- 冲突升级

专业智能体：
- 产品智能体
- 架构智能体
- 开发智能体
- 测试智能体

核心原则：

> 简单任务走短路径，复杂任务才拉完整团队；执行问题内部解决，方向问题上报项目负责人。
