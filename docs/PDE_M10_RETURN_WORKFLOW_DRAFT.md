# PDE M10｜返校核对业务流程草案 v0.1（待负责人确认）

> 日期：2026-10-12
> 阶段：业务流程澄清；**不是已经开发完成的 M10 功能，也不代表已获得学校真实数据处理权限。**
> 基线：M9 独立浏览器本地试点已通过 Windows 业务核对、10 项规则自检与 5 条虚构记录 WPS CSV 导出验收。
> 交付原则：一个有价值的角色协作闭环，一次统一验收；避免重复建设测试模块和预设过多业务规则。

## 一、要解决的实际工作问题

1. 学生预计返校日期变更、临时离校或最初填报留校，均可能与后来实际晚间在校情况不一致。
2. 晚间考勤以某一天为单位，不能把学生一次自报、前一晚到校或未填报等同于当晚实际情况。
3. 学生助理要整理上报表，但不宜承担代替生活委员检查全班晚间到校的责任。
4. 辅导员只需及时看到有证据的异常、尚待核实事项，并能找到对应的原始记录。

## 二、待确认的最小协作流

学生自报/变更预计返校计划
  → 按班级建立待核对名单
  → 生活委员填当日晚间实际考勤
  → 系统按「日期 + 学生」对比并形成异常待办
  → 辅导员核实异常、保留处理记录
  → 学生助理导出校方要求的核对结果（经辅导员确认）

各角色责任：

- **学生：** 仅管理本人当期状态和预计返校计划；变更保留时间与旧值。不得修改生活委员的考勤证据。
- **生活委员：** 只负责所属班级的某一天晚间考勤；考勤未提交、未见本人、确认未到必须区分。
- **辅导员：** 查看跨班级异常和原始证据，记录联系/核实结果，确认哪些可以出现在正式汇总里；不能直接把学生自报当作到校证明。
- **学生助理：** 在授权范围内汇总及导出校方表格；不代替晚间考勤、不得擅自改写原始记录。

## 三、建议保留的最小数据结构（概念层）

### 基础人员

由可信学校名单形成一人一个稳定标识（校区、学院、班级、姓名、学号），身份、班级归属及授权不能由学生任意修改。本阶段仅虚构数据。

### 自报计划记录

包含学生标识、留校/离校/预计返校等自报信息、预计日期或时间段、变更时间、来源；变更应追加版本，不覆盖上一版原值。晚间在校状态不写回自报字段。

### 晚间考勤记录

独立的 `date + class_id + student_id` 维度，状态建议 `在校 / 未在校 / 未核实`；区分「该日整班尚未提交」与「该学生暂未核实」。支持登记人、填报时间及更正轨迹。此前某日「在校」**不能证明今日仍在校**。

### 人工核实记录

异常类型、对应的自报与某日晚间考勤、辅导员核实结论/说明/时间、必要的后续跟进状态。没有核实证据时保持待办，不能自动变成已确认到校。

## 四、最初可以自动提示、但不能直接定责的状态

- **计划与考勤矛盾：** 自报已返、填留校，但某日晚间记录明确不在校。
- **到期尚未到校：** 预计返校日期已经到或过去，当晚明确不在校。
- **尚未核实：** 当天考勤未提交或个人考勤未知；不得直接按缺勤、违纪处理。
- **当晚确认在校：** 有对应日期晚间考勤的「在校」记录，仍保留原学生计划并注明证据日期。
- **计划未来返校：** 预计日期未到且尚无当晚在校证据，不当作逾期。

上面状态名称、何时触发提醒、是否按中午/晚上分时段、是否把工作日晚间考勤纳入长期业务，均属于需确认的口径，不在本草案阶段锁死。

## 五、首要待决定问题：生活委员具体怎样提交晚间考勤？

此处不能自作决定。两种实际可用的交互方式：

**方案 A｜全班名单快速点名（建议优先评估）**
系统显示当晚全班名单，生活委员批量确认/逐人调整，最后明确提交，未提交与全员到校绝不能混为一谈。优点是结果完整、可核查；代价是每晚操作较多。

**方案 B｜只登记异常**
先根据班级应到名单，仅上报未在校、请假或异常人员；操作少，但需要明确区分「全班核实无异常」与「忘了上报」，否则容易把未提交误判为全员到校。

**待负责人回答：** 你们晚间考勤实际上更接近 A（全员逐个点名）还是 B（只报异常名单）？若两者混合，也请描述目前怎么做。

## 六、确认后才进入的完整 M10 可操作原型

在仅用虚构名单、与正式辅导员工作台隔离的前提下：

1. 学生修改预计返校日期；
2. 生活委员为指定日期提交该班晚间考勤；
3. 系统重新计算待核实/冲突/逾期人员，不覆盖原始记录；
4. 辅导员打开异常清单，核实一条并留下记录；
5. 学生助理依据授权导出一张标识核实状态的 CSV；
6. 统一测试：未提交、重复提交、更正、预计日期变更、历史考勤不误用、浏览器导出。

**重要边界：** 浏览器里的模拟角色切换不等同真实登录鉴权。未经数据治理确认，不能将本地试点直接部署为管理真实学生信息的系统，也不能在现有辅导员工作台直接写入数据库或旧数据。此处不预先定义学生端链接、生活委员账号或学校表格格式。
