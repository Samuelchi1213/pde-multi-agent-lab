# PDE M10｜返校核对多角色流程 v0.2（已确认 B：只登记异常）

> 日期：2026-10-12
> 决策：**生活委员每晚采用 B 模式：只登记异常人员，不要求逐个点名全班。**
> 状态：流程规格已确定，等待集中实现一个可操作的虚构数据协作闭环；**目前没有生产数据接入和真实身份授权**。
> 基线：M9 本地核对、CSV 导出及 WPS 打开已经 Windows 验收。

## 一、最关键的业务规则

**「没有登记异常」和「已经核对、确认无异常」不同；二者也都不等于「每个学生本人已核实返校」。**

- 未提交：当晚班级考勤信息缺失，显示「班级未提交」。不得计算零异常、全员到校或全员缺勤。
- 已提交无异常：生活委员明确点击「本晚已核对，无异常」提交，含日期、班级、填报者及时间。表示本晚班委未报异常，**不是每个学生的到校证明**。
- 已提交有异常：生活委员从班级名单挑选异常学生，仅给被登记者生成「本晚异常待核实」。未被列出的学生保持「当晚未报异常」，不能自动标记已返校。
- 不得沿用前一晚记录为今天的考勤结果。单次学生自报或昨晚确实到校也不能证明今天在校。

## 二、四类角色的最小协作闭环

学生自报/更新计划 → 生活委员每日选择班级、日期并报异常（或明确零异常提交） → 系统生成对应日期的异常/待核实清单 → 辅导员联系核实并留下证据 → 学生助理仅按确认范围导出表格。

### 学生

只填写或修改本人留校、离校、预计返校计划。修改预计日期必须追加时间戳及旧值，不能覆盖历史版本；学生不能修改晚间考勤和辅导员核实记录。

### 生活委员（明确 B 模式）

1. 选择今天（或获准补录的日期）和本班，查看「今晚尚未提交」状态。
2. 如有异常，搜索本班学生，选择类别：**未见到/疑似未在校、报告请假、其他待核实**；可填写备注。登记「未见到」仅是班委观察，不是违纪定责。
3. 如果本晚核对后没有发现异常，必须主动点击「已核对、无异常」完成提交；不用逐个点击「到校」。
4. 同班同日只能有一条当前有效提交。重复点击不能生成重复记录；修正已提交信息要留下旧版本、更正人、时间和原因。
5. 正式系统必须限制只可提交其负责的班级；模拟角色切换不能当作真实权限。

### 辅导员

系统展示：班级未提交、具体异常人员、自报与异常相冲突的学生、预计返校时间已到但缺乏个人确认依据的学生。辅导员可以联系核实，记录「确认当晚在校、确认当晚不在校、继续跟进」等**人工核实结论**及依据日期；不更改学生原自报或班委填报。无异常提交不直接产生「该生已返校」结论。

### 学生助理

在辅导员核准的模拟范围内整理及导出；不得编辑原始自报、班委考勤或辅导员核实。导出至少含班级、日期、学生标识、最新自报计划、当晚班级提交状态、该生异常详情、人工核实状态及备注。缺少实际核验时输出「待核实」，而不是「已到校」。

## 三、最小数据结构与证据来源

| 记录 | 唯一标识 | 最小字段 |
|---|---|---|
| 虚构学生名单 | student_id | 校区/学院/班级/姓名/模拟学号 |
| 自报计划历史 | student_id + version | 留校离校、自报返校状态、预计返校日期、提交时间、旧值 |
| 班委晚间考勤提交 | class_id + attendance_date | 未提交/已提交无异常/已提交有异常/已修订、填报人、提交时间、版本 |
| 异常名单 | submission_version + student_id | 未见到/报告请假/其他待核实、备注、修订轨迹 |
| 辅导员核实记录 | date + student_id + version | 人工核实结论、来源依据、联系备注、核实时间 |
| 导出快照 | 所选日期 + 已审核范围 | 原自报、对应日期班委提交及异常、辅导员核实结果、待跟进标识 |

关键规则：异常名单记录是当晚的班委报告，**没有被列为异常不等于已核实返校**；当晚未提交也不等于零异常。核实记录不能反向覆盖原始数据。

## 四、计算与提醒口径

1. 本班当晚未提交 → **班级待提交**，不推断全员到校或缺勤。
2. 本班明确提交无异常 → **班委本晚已提交，无异常上报**，个人到校证据仍可能缺失。
3. 某生被报「未见到」，且学生自报「已返校」或「留校」 → **自报与当晚异常冲突，待辅导员核实**。
4. 某生被报「未见到」，预计返校日期到期或已过 → **到期未见，待跟进**；不能自动算违纪。
5. 某生被报「请假」 → 保留请假陈述及未核实属性，不当作无故缺勤。
6. 预计返校日已到、班委已报无异常，但无单人确认 → 可进入**到期待确认关注清单**，不可自动算已返校。
7. 学生修改预计返校日期 → 后续提醒按照最新计划计算，但历史记录不可消失。
8. 以前日期的在校、无异常、未见到等证据都不能自动沿用到新日期。

提醒是否按中午/晚上发送、学校要求何种导出模板，以及真实数据接入，均需后续单独确认。M10 原型不自动向学生发送通知。

## 五、集中开发的完整可操作原型

使用同一套虚构名单、与 M9 及正式辅导员工作台隔离，一次性交付：

- 区域① 学生：填写及修改预计返校日期，查看修改历史。
- 区域② 生活委员：选择班级和日期，仅登记异常；支持「确认当晚无异常」明确提交、重复提交防护、修订留痕。
- 区域③ 辅导员：查看某日班级未提交、异常人员、自报冲突、到期待确认；对某学生登记核实结论和联系备注。
- 区域④ 学生助理：模拟辅导员授权后生成包含证据日期及待核实状态的 CSV。

使用浏览器内存及虚构数据；角色切换只是演示，不代表真实登录鉴权；禁止读取真实学生名单，禁止修改已有辅导员工作台项目。

## 六、一次统一验收（不是每个按钮单独验收）

1. 无异常班：先验证未提交，再明确提交「本晚无异常」，不应将全班标记为「本人已核实到校」。
2. 另一班：班委只登记一名「未见到」学生并提交；系统生成对应的待核实或自报冲突。
3. 学生修改预计返校日期：新提醒依据最新计划，旧计划能回看。
4. 辅导员处理一条异常，原始班委提交记录保持不变。
5. 学生助理仅在辅导员模拟批准后导出 CSV，WPS 打开显示当晚班委状态、个人异常、核实状态。
6. 验证同日重复提交不新增第二份记录，修订保留历史；下一日不沿用上一晚结论。
