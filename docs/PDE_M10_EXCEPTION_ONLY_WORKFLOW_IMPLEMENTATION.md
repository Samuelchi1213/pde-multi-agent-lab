## 交付结果

PDE 控制台首页新增「M10｜返校核对四角色协作 · 生活委员只报异常（B模式）」入口：

- 点击打开独立页面 /m10/return-workflow。
- 同一套**7 名虚构学生、2 个虚构班级**贯穿四角色。
- ① 学生：修改模拟自报与预计返校日期；系统追加新版本，保留旧历史。
- ② 生活委员：选择日期和班级，只登记异常学生。发现零异常时必须主动点击「明确提交：本晚已核对，无异常」。未提交和零异常不等同；同日重复提交被阻断，如需修订必须改动内容并填写原因，旧版本保留。
- ③ 辅导员：按当晚日期集中查看班级待提交、实际异常、自报冲突、到期待确认；记录带引用考勤版本的核实结论和备注，原班委考勤与学生自报不受修改。班委事后修订考勤后，旧核实提示「需重新核实（考勤已修订）」。
- ④ 学生助理：模拟辅导员批准后才能导出 7 条虚构记录。导出包含两班提交状态、考勤版本、个人异常、计划、自报历史版本、人工核实状态与备注；批准后只要数据再变化就自动失效，必须重新批准。
- 导出方式继承 M9 问题修复经验：Blob 自动下载 + 页面保留手动下载链接 + Edge 支持的「指定位置另存为 CSV」。

## 最核心的判断规则

1. 班级**未提交**：不能自动推断无异常，也不能判断全班到校。
2. 班级**明确提交无异常**：表示班委当晚未报告异常，**不能自动把某位学生认定为已核实返校**。
3. 提交异常：只对列表中的人创建异常证据；未列名者不代表本人到校。
4. 自报「已返校/留校」且被当晚报「未见到」→ 自报与当晚异常冲突，交辅导员核实。
5. 预计返校日期已到但没有个人到校证据 → 到期待确认，不直接定责。
6. 考勤按「班级 + 日期」隔离；历史零异常或历史在校不能证明其他日期情况。
7. 班委考勤合法修订后，先前引用旧考勤版本的人工核实不能继续被显示为当前有效结论。

## Windows 一次性完整业务验收

1. 在 PDE 点击检查更新，更新后 **完全退出控制台并重新启动**。
2. PDE 首页打开 **M10 四角色协作演练**，点击「加载虚构团队」，默认显示 7 名示例学生、2 个班级，确认全班都「未提交」。
3. **学生区**：选择示例甲，把预计返校日期改为更晚的一个有效日期，点击保存，检查历史保留旧版本。
4. **生活委员区**：先选择「电商2班」，点击「明确提交：本晚已核对，无异常」，确认状态「已提交无异常」，并检查辅导员页不能因此出现全班已返校。然后选择「会计1班」，选择示例甲，异常「未见到」，加入草稿并点击「提交本晚异常名单」；对应状态应进入异常待核实（示例甲如已改为「未返校」且预计日期未来，则不会继续提示自报冲突）。
5. **辅导员区**：选择示例甲，填写至少 2 字联系备注，保存「继续跟进」或其他核实结论。检查其核实历史与班委提交历史分别存在。
6. **助理区**：先点导出，必须显示未获模拟批准；返回辅导员区点击「辅导员模拟批准本日助理导出」，再导出 CSV，用 WPS 打开确认 **7 行虚构学生、两班当日提交状态与个人核实字段**。
7. **修订与失效**：回生活委员区，对会计1班点击「加载已提交记录以修订」，移除原异常，填写原因，再点「明确提交：本晚已核对，无异常」。辅导员页原核实应显示 **「需重新核实（考勤已修订）」**，助理此前的模拟批准必须失效；重新模拟批准才能导出。
8. 需要时点击页面顶部「运行业务规则自检」，应显示 **12 项通过**。不需要重新运行 M8/M9 的旧回归测试，也不需要逐步骤截图。验收反馈建议 1 张最终业务页截图 + CSV 是否能在 WPS 打开。
