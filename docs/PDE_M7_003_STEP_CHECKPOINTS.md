## 业务问题

PDE 曾出现 QA 已经收到 DeepSeek 结果、却因预算判断和中断造成“继续执行”的上下文不清楚；同一草案重新启动又可能重复调用 Codex，浪费付费额度并覆盖原产物。

M7-002 让系统能正确识别中断；M7-003 要解决“中断以后到底什么能继续、什么绝对不能自动重复执行”。

## 最重要的一条设计原则

**只允许继续尚未发出外部调用的步骤；已有可校验结果的步骤复用本地凭据；已开始但结果未知的外部调用一律停止，必须人工确认后再采取下一步。**

不要把 API 超时、断线、状态文件仍显示运行中解释为“肯定没有调用成功”。

## A 阶段：已提交的安全基础设施

`web_console_v1/step_checkpoints.py`：

- 每次任务单独一个 `step_checkpoints.json`，不会自动新建已有任务目录。
- `reserve_step(run_dir, step_id, inputs)`：外部调用前写入步骤预约。
- `finish_step(run_dir, step_id, inputs, receipt)`：调用后，只有已保存并验证非空、本目录内的凭据文件，才能将步骤标为完成。
- `inspect_step(...)`：只读查看，检查输入指纹是否一致、结果凭据是否存在以及 SHA-256 是否匹配。
- `mark_uncertain(...)`：记录未知状态但不自动授权再次调用。
- `list_steps(...)`：安全摘要，不暴露模型回复、Prompt 或密钥。
- 文件原子写入、步骤锁 `.step_checkpoints.lock` 防止不同进程同时预约同一阶段，崩溃锁不自动窃取，必须人工诊断。
- 请求输入只保存 SHA-256 指纹，不保存完整 Prompt 或 API 密钥；回执写在现有业务许可的隔离工作区内，检查点只保存其相对路径/哈希/字节数。
- 旧 `dynamic_runs` 任务不会自动加检查点或追认已完成阶段，也不重新运行。

关键判定：
| 检查点情况 | `decision` | 能否再次触发付费调用 |
|---|---|---|
| 没有该步骤记录 | `not_started`；正式预约成功返回 `reserved` | 仅在明确新任务流程中，预约成功后才允许 |
| 已预约、尚无成功凭据 | `blocked_uncertain` | **不能** |
| 已标记结果未知 | `blocked_uncertain` | **不能** |
| 完成且输入指纹、结果证据哈希均匹配 | `reuse_saved_result` | **不能**，应读取已有结果 |
| 同一步骤输入变化 | `blocked_input_changed` | **不能**，须新步骤编号及授权 |
| 回执丢失、被改动或越界 | `blocked_missing_evidence` / `blocked_evidence_changed` | **不能** |
| 检查点文件损坏/存在锁冲突 | 抛出 `CheckpointError` | **不能** |

> 注意：`reserve_step` 的存在不代表网络请求成功，`completed` 也不代表端到端测试通过；它只证明可复用的**本地输出证据**存在。

## 离线测试

新增 `web_console_v1/test_step_checkpoints.py`，18 项场景：
- 初次预约与重复预约；
- 具备完整结果凭据后复用；
- 相同输入字段不同顺序保持一致；
- 输入变化阻止复用；
- 结果未知绝不重试；
- 原 Prompt 和密钥不写入检查点；
- 结果文件丢失、篡改、越界后不复用；
- 锁冲突、损坏文件、尚未预约就完成等均拒绝；
- 结果摘要不泄露实际 AI 回答。

浏览器操作：更新 PDE、重新启动，然后展开“开发 / 诊断工具”，点击 **“验证步骤防重复（离线）”**。预期 18 tests、exit code 0、步骤自检通过。

原 M7-002 的“验证任务状态恢复（离线）”仍为 13 项，两个按钮独立。

## B 阶段：未实现（必须另行设计、上线与验收）

**此阶段不直接改动 `DynamicTeamRun.run()` 的模型调用路径。** 在真实流程接入检查点前，至少需要：

1. 明确所有步骤 ID：`product.spec`、`architecture.plan`、`developer.first`、`tests.round0`、`qa.round0`、`developer.rework1`、`qa.round1`、`manual_rework1` 等；避免不同轮次相互覆盖。
2. 每个模型执行器调用前必须先预约、调用结果落盘且 SHA 校验后才标完成；对 Codex 还要保存隔离工作区版本摘要，防止复用与实际代码不匹配的交付。
3. 读取已有结果只可复用**指纹匹配**的回执，模型调用已计费但来不及写结果时进入“结果不确定”，不得在界面直接呈现“继续”按钮。
4. 旧版不带检查点的任务按旧流程只读检查，**不得自动迁移成可重放**。
5. 审批同意的是具体步骤/额外费用，须记录操作者、批准时间、成本上限；未知结果的手动新尝试应生成新 ID，保留上一轮痕迹。
6. 对重启、断电、重复点击、文件篡改、修改模型参数、两个标签页同时操作、历史任务和候选安全发布做端到端回归测试。
7. 不允许为方便重新执行整团队而删除 `state.json`、隔离工作区、审计记录或真实项目数据。
